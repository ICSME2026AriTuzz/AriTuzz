# BCM2835 DMA: Unsigned Underflow in Transfer Length

## Summary

This bug is triggered when the guest provides a transfer length smaller than the DMA step size. The emulator subtracts a fixed 4-byte unit from an unsigned counter without checking whether the counter is already below 4. Once the counter wraps, the loop keeps running and the DMA engine continues reading and writing far beyond the intended transfer.

## Trigger Chain

1. The guest submits a DMA control block with a very small transfer length.
2. The DMA loop copies one 32-bit word per iteration.
3. The remaining length is decremented by 4.
4. If the initial length is not a valid multiple of 4, the unsigned counter wraps to a huge value.
5. The loop no longer terminates in any reasonable time and may keep touching memory.

## Vulnerable Logic

```c
uint32_t remaining = txfr_len;

while (remaining != 0) {
    copy_one_word();
    remaining -= 4;
}
```

## Fixed Logic

```c
if (txfr_len == 0 || (txfr_len & 3) != 0) {
    report_dma_error();
    stop_transfer();
    return;
}

while (remaining != 0) {
    if (remaining < 4) {
        report_dma_error();
        break;
    }
    copy_one_word();
    remaining -= 4;
}
```

## Analysis

This is a classic arithmetic-boundary bug. The dangerous part is not a complicated state machine, but a silent unsigned wraparound on a guest-controlled length field. Once the value crosses zero, the loop turns a tiny transfer into a near-unbounded operation, which is enough for denial of service and potentially unsafe memory access.
