# PL080 / PL081 DMA: Width Decoding Causes Stack Overflow

## Summary

This sample comes from an unchecked conversion of encoded width fields into byte counts. The guest controls small width fields in the DMA descriptor, but the emulator expands them into actual transfer widths without validating reserved values. A local stack buffer is only 4 bytes wide, so oversized decoded widths lead directly to stack corruption.

## Trigger Chain

1. The guest sets source and destination width fields to invalid reserved encodings.
2. The emulator converts those encodings into large byte widths.
3. A fixed-size local stack buffer is used as the temporary transfer buffer.
4. Read or write operations use the oversized widths against that buffer.
5. Stack memory beyond the buffer is overwritten.

## Vulnerable Logic

```c
uint8_t tmp[4];

swidth = 1u << src_width_field;
dwidth = 1u << dst_width_field;

for (n = 0; n < dwidth; n += swidth) {
    dma_read(src, tmp + n, swidth);
}
```

## Fixed Logic

```c
uint8_t tmp[4];

swidth = 1u << src_width_field;
dwidth = 1u << dst_width_field;

if (swidth > sizeof(tmp) || dwidth > sizeof(tmp)) {
    report_guest_error();
    ignore_channel();
    return;
}
```

## Analysis

This bug is simple and nasty. The emulator trusted an encoded field too early and converted it into a real memory size before checking whether the value was legal. Once that happens, a tiny stack scratch buffer becomes a write target for much larger transfers, which is the shortest possible path from guest input to host memory corruption.
